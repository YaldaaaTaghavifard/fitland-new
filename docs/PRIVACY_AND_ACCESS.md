## ۱. مدل کنترل دسترسی مبتنی بر نقش (RBAC Matrix)

سامانه فیت‌لند از معماری کنترل دسترسی مبتنی بر نقش (Role-Based Access Control) بهره می‌برد. سطوح دسترسی به تفکیک منابع سامانه به شرح جدول زیر است:

| منبع / عملیات | بازدیدکننده (Guest) | عضو باشگاه (Member) | مربی (Trainer) | مدیر سیستم (Admin) |
|:---|:---:|:---:|:---:|:---:|
| مشاهده صفحات عمومی (خانه، درباره ما، مربیان، پلن‌ها) | ✓ | ✓ | ✓ | ✓ |
| مشاهده و مطالعه پرونده کسب‌وکار (`/business-case`) | ✓ | ✓ | ✓ | ✓ |
| رزرو کلاس ورزشی | ✗ (نیاز به ورود) | ✓ | ✗ | ✓ |
| دسترسی به درگاه پرداخت و تقسیط آزمایشی | ✗ | ✓ | ✗ | ✓ |
| ثبت و مشاهده اندازه‌گیری‌های تن‌سنجی شخصی (قد، وزن، دور کمر) | ✗ | ✓ | ✗ | ✗ |
| مشاهده برنامه تمرینی و تغذیه اختصاصی | ✗ | ✓ | ✗ | ✗ |
| نگارش و ویرایش برنامه تمرینی و تغذیه برای شاگردان | ✗ | ✗ | ✓ | ✓ |
| ثبت بازه‌های زمانی تقویم کاری مربی | ✗ | ✗ | ✓ | ✓ |
| مشاهده لیست کل کاربران و تغییر نقش‌ها | ✗ | ✗ | ✗ | ✓ |
| دسترسی به گزارش‌های فروشگاه و ویرایش موجودی | ✗ | ✗ | ✗ | ✓ |
| اجرای پایشگر آزمون سناریوها (Scenario Runner) | ✓ | ✓ | ✓ | ✓ |

## ۲. حریم خصوصی داده‌های حساس تندرستی (Health & Biometric Privacy)

- **ایزوله‌سازی سوابق تن‌سنجی:** اطلاعات بدنی، شاخص توده بدنی (BMI) و سوابق وزن هر عضو تنها برای خود او و مربی اختصاصی‌اش در صورت انتساب معتبر قابل مشاهده است.
- **پردازش محلی (Client-Side Isolation):** در این نسخه آزمایشی، داده‌های سلامت بر روی مرورگر کاربر نگهداری شده و به سرورهای تبلیغاتی ثالث ارسال نمی‌گردد.

---

## ۳. سیاست شفافیت و عدم دریافت اطلاعات واقعی مالی (Zero-Leakage Policy)

- **اطلاعات کارت‌های بانکی:** هیچ‌گونه شماره کارت، رمز دوم (پویا)، CVV2 یا تاریخ انقضای واقعی از کاربر درخواست نمی‌شود. تمامی فرم‌های پرداخت به شکل پیش‌فرض با داده‌های نمادین و واضح پر شده‌اند.
- **برچسب‌گذاری Mock/Demo:** در تمامی مراحل انتخاب پلن، شبیه‌سازی پرداخت و صدور فاکتور، پیام اخطار شفاف مبنی بر آزمایشی بودن تراکنش به کاربر اعلام می‌شود تا هیچ ابهامی در ماهیت دانشگاهی و آموزشی پروژه پیش نیاید.

---

## ۴. مدیریت نشست و انقضای حساب (Session Security)

- ورود و خروج کاربر از طریق `AuthContext` مدیریت می‌شود.
- در هنگام خروج (`logout`)، وضعیت احراز هویت پاکسازی شده و توکن یا شناسه نشست از حافظه جاری حذف می‌گردد.
- ورود مستقیم کاربر به مسیرهایی که در ماتریس RBAC برای نقش او مجاز شناخته نشده‌اند، توسط کامپوننت `ProtectedRoute` مسدود گردیده و کاربر به صفحه خطای ۴۰۳ (`/unauthorized`) منتقل می‌شود.
